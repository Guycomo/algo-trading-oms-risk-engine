# Algorithmic Trading System with OMS and Risk Controls

An end-to-end order management system (OMS) for algorithmic trading that takes a trading signal, routes and tracks orders, enforces real-time risk limits, and provides live monitoring of positions, P&L, and risk utilization.

The focus of this project is the **trading infrastructure**, not the trading signal itself — a simple, well-documented strategy is used deliberately so the system built around it (order handling, risk enforcement, monitoring) is what stands out.

## Motivation

Most trading portfolios show a strategy. Very few show the infrastructure that keeps a strategy running safely — order state management, position tracking, and risk limits that stop a bad day from becoming a catastrophic one.

This project builds that infrastructure from scratch, to demonstrate:

- How orders are tracked through their full lifecycle (submitted, partially filled, filled, cancelled, rejected)
- How a system enforces hard risk limits automatically, without relying on a human to intervene in time
- How a trading desk monitors live risk exposure, not just live P&L

This is the kind of system-building skill that trading desks specifically look for at the junior and associate level, since it shows an understanding that trading is as much about not blowing up as it is about making money.

## Data Source

Live market data and simulated order execution are pulled from an exchange **testnet**, for example **Binance Futures Testnet**, which provides realistic price data and a simulated trading account funded with test capital. No real funds or KYC are required.

Data collected includes:

| Data Point | Purpose |
|------------|---------|
| Live price data | Signal generation and mark-to-market valuation |
| Order acknowledgements and fills | Order state tracking |
| Account balance and open positions | Position and exposure tracking |
| Timestamped risk metrics | Risk limit monitoring over time |

## Methodology

1. **Implement a simple trading signal** (for example, a basic moving average crossover or breakout rule). The signal is intentionally kept simple, since it is not the focus of this project.
2. **Build the order management layer**, which:
   - Submits orders generated by the signal
   - Tracks each order's full lifecycle (submitted, partially filled, filled, cancelled, rejected)
   - Handles retries for failed or rejected order submissions
3. **Build the position tracking layer**, which maintains a live view of current holdings, average entry price, and unrealized P&L, updated as fills are received.
4. **Build the risk control layer**, which enforces limits automatically:
   - Maximum position size per instrument
   - Maximum daily loss limit
   - An automatic kill switch that flattens all positions and halts trading if a limit is breached
5. **Build a live monitoring dashboard** that displays current positions, live P&L, and current risk utilization (for example, how close the system is to its daily loss limit).
6. **Log every order, fill, risk check, and kill switch event** with timestamps for post-trade analysis.
7. **Run the full system over an extended period** to observe how it behaves under normal conditions and, ideally, during at least one simulated or naturally occurring risk limit breach.

## What This Project Analyzes

- **Order execution reliability** — how consistently submitted orders reach the exchange and get correctly tracked through their lifecycle
- **Risk limit enforcement** — whether the kill switch and position limits trigger correctly and promptly when thresholds are breached
- **System uptime and error handling** — how the system responds to dropped connections, rejected orders, or unexpected data
- **Post-trade summary** — a clear log of every action the system took and why, which functions as an audit trail

## Tech Stack

- **Python** — signal logic, order management, and risk engine
- **Exchange WebSocket and REST API** (e.g., Binance Futures Testnet) — live market data and order execution
- **A data storage layer** such as a lightweight local database (e.g., SQLite) for order state, position, and risk event logging, since this project requires more structured record-keeping than the earlier two
- **A simple dashboard framework** (e.g., Streamlit) for the live monitoring view
- **Matplotlib or Plotly** — visualizing P&L and risk utilization over time in the post-trade report

## How to Run

1. **Clone the repository**
   ```
   git clone <repository-url>
   cd algo-trading-oms-risk-engine
   ```

2. **Set up a virtual environment**
   ```
   python -m venv venv
   source venv/bin/activate
   ```

3. **Install dependencies**
   ```
   pip install -r requirements.txt
   ```

4. **Create a testnet account and API key** on the chosen exchange testnet, and add the credentials to a local configuration file (never commit API keys to the repository).

5. **Configure risk limits** (maximum position size, daily loss limit) in the risk configuration file before starting the system.

6. **Run the trading system**
   ```
   python oms/order_manager.py
   ```

7. **Launch the live dashboard** in a separate terminal
   ```
   streamlit run dashboard/live_monitor.py
   ```

8. **Generate the post-trade report** after a monitoring session
   ```
   python analysis/postmortem_report.py
   ```

9. **View results** in the `results/` folder, including the full event log and generated charts

## Limitations

- Runs on testnet data, so order behavior and fills may not perfectly match a live, real-money environment
- The trading signal used is intentionally simple and is not the focus of this project's evaluation
- Risk limit values are set manually rather than being dynamically calibrated to changing market volatility
